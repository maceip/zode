# Zode — Android client

The same app as the web version, in Jetpack Compose, with a pre-2011 **Metro** look:
square tiles with zero corner radius, flat fills, a near-black or warm-paper canvas,
light-weight large display type, uppercase tracked labels, and a horizontal collection
carousel.

Five views — **Now Playing**, **Collection**, **Library**, **Search**, **Agent** — with
the same intents and the same haptic programs as every other Zode surface.

## Build

```bash
export ANDROID_HOME=$HOME/Android/Sdk      # or your SDK location
./gradlew :app:assembleDebug                 # -> app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:installDebug                  # onto a connected device
```

> **`gradle/wrapper/gradle-wrapper.jar` is committed**, so `./gradlew` works from a
> fresh clone with no extra setup. It was generated by
> `gradle wrapper --gradle-version 8.11.1`, not hand-made. Regenerate it with the same
> command if you need to.
>
> `local.properties` is gitignored — it points at your SDK.

The CI workflow (`.github/workflows/ci.yml`) regenerates the wrapper jar and runs the
same build on a real runner.

```
  haptics/             the CoreHaptics-equivalent: VibrationEffect rendering

  ui/                  the five views
app/src/main/res/raw/  haptics.json, library.json  (copies of packages/shared/)
```

## The shared files

`res/raw/haptics.json` and `res/raw/library.json` are **byte-identical copies** of
`packages/shared/haptics.json` and `packages/shared/library.json`. The library is
generated from the web app, so this client presents exactly the same records as
`apps/web` — it never invents its own catalogue.

```bash
python3 ../../scripts/export_library.py           # republish
python3 ../../scripts/export_library.py --check   # verify every copy agrees
```

## Haptics

`packages/shared/haptics.json` is rendered with `VibrationEffect.createWaveform`:
every 25 ms the intensity curve is sampled into an `(timing, amplitude)` pair with
`intensity × 255`, a `transient` track becomes a short high-amplitude pulse, and
`working` repeats forever (`repeat = 0`).

Two platform limits worth knowing:

- `VibrationEffect.Composition` can only compose the built-in **primitives**, and
  `Vibrator` has no `compose` — so two arbitrary waveforms cannot be layered. All the
  tracks of a program are merged onto one timeline instead.
- For the same reason, a one-shot that arrives while the `working` loop is running
  replaces the loop and the loop resumes when the one-shot ends.

`capabilities.haptics` is reported honestly: it is `true` only when the device
actually has a vibrator.

```bash
python3 ../../mobile/android/tools/verify_android.py   # static contract checks
```

## Not verified here

The app **compiles and assembles** — a real APK is produced. What has *not* been
confirmed on hardware is the runtime behaviour: how the vibration actually feels on a
given device, the pull-to-refresh and deep-link paths, and the notification channel's
appearance in the system shade.
