# Zode — web app deliverable

The Zune-era × Microsoft Metro web app that the native macOS and Windows
shells host in a system webview. Plain ES modules, JSDoc types, plain CSS —
**no build step, no bundler, no npm install, zero runtime dependencies**.

Everything below was run in this environment; the outputs are copied verbatim.

---

## 1. Summary

I implemented the complete web app in `/workspace/zode/apps/web`: a bridge
adapter that installs the **full contract §2 surface** (`window.zode`) on top
of a platform transport (§1) or the §6 browser shim, the app shell (drag strip
per §5, Metro left rail, router, playback clock), the five views (Now Playing,
Collection, Library, Search, Agent), a seeded deterministic library and a fake
agent engine. The haptics are rendered from `packages/shared/haptics.json` by
a WebAudio synthesiser that the Windows shell is expected to mirror. The
self check (`node selfcheck.mjs`) boots the real app in a DOM stub and passes
**35/35** checks, exiting 0; every file the app references is served 200 by
the dev server.

## 8. Deliberate deviations, and what I could NOT do

1. **§6 says the shim "MUST live in `packages/shared/`".** `packages/shared`
   is frozen and this task may not write outside `apps/web/`, so the shim lives
   in `src/bridge/web-fallback.js`. To keep it a faithful mirror of the frozen
   data, `assets/haptics.json` and `assets/tokens.css` are **byte identical
   copies** of the shared files, and `tools/sync-shared.mjs` re-copies them
   (`--check` fails on drift). The self check asserts the copies match. If the
   shim is ever moved into `packages/shared/`, only the import path in
   `src/bridge/zode.js` changes.
2. **No browser rendering verification.** This sandbox has no browser binary
   (`which chromium google-chrome firefox` → nothing, no puppeteer/playwright),
   so I could not take a screenshot or run the CSS. What *is* verified: the
   DOM the app builds (the self check asserts the Now Playing title, the 50
   library rows, the 30 collection tiles, the search field, the composer, the
   live region and the wordmark are all present and non-empty), and that every
   stylesheet and asset is served with 200. The CSS itself was written by hand
   against the tokens and has not been rendered by a layout engine.
3. **The native transports are implemented but not exercised.** `detectPlatform`
   recognises `window.webkit.messageHandlers.zode` and `window.chrome.webview`,
   and the bridge posts the §1 envelope and waits for the matching response —
   but no macOS/Windows shell exists in this environment, so only the request
   side and the response plumbing could be reviewed, not a real round trip.
   The self check drives the native *event* path instead
   (`window.__zodeNative__({type:'event', …})`).
4. **No audio decoding.** The player is a deterministic clock, not a decoder —
   the brief asked for the views and the transport, not an audio engine.
5. **`capabilities.journal` is `false` in a browser** (there is no system
   journal); `zode.journal()` still resolves and the shim records the entry in
   a local log. Likewise `zode.openPath()` fails with `code: 'unsupported'`
   rather than pretending to work. `capabilities.windowControl` is `true` in a
   browser because fill/fullscreen works there — the *drag* half is a no-op in
   a browser, by design.
6. **Haptic playback needs a user gesture.** Browsers refuse to start an
   `AudioContext` before one; the shim resumes the context on the first
   `pointerdown`/`keydown` (`src/bridge/web-fallback.js:98`).

## 9. How the shells should host it

* Copy the **whole** `apps/web/` folder (including `assets/`) into the bundle.
* Serve it from a stable origin — `zode://app/` on macOS,
  `https://app.zode.local/` on Windows. Never `file://`: the haptic programs
  are loaded with `fetch` (`src/bridge/web-audio-haptics.js:367`).
* The shells must evaluate `window.__zodeNative__({type:'event', event, payload})`
  to push events; the bridge installs that entry point
  (`src/bridge/zode.js:330`).
* A shell may answer `app.info` with an extra `capabilities` object to refine
  `window.zode.capabilities` (`src/bridge/zode.js:144`).
* The Windows shell should mirror `src/bridge/web-audio-haptics.js` — the
  contract §7 envelope, curve and loop semantics live there.
